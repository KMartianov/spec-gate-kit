> Любая правка кодовой базы до `approved` блокируется плагином `spec-gate`
> (`[SPEC-GATE BLOCKED]`). Утверждает **человек**, не агент.
>
> **Мандат записи — `scope`, а не сам факт одобрения.** После `approved` запись
> разрешена только для путей, покрытых машинным ограждением `scope` (см. §3) и не
> покрытых его `deny`; нет ограждения / пустой `allow` / битый JSON ⇒ мандата нет
> (fail-closed). `docs/**` закрыт безусловно (GOV-2), `.slim/spec/**` всегда
> writable. Класс файла объявляет статусная строка: `roadmap`/`index` — индекс
> портфеля, а **не** контракт (ни мандата, ни `dod`-контура); иной токен —
> контракт; строки нет — `undeclared` (тоже не контракт). Правка спеки после
> одобрения меняет хеш и **инвалидирует approval**.

### Ограждение `scope` — машинный мандат записи (GOV-1)

Ограда с info-строкой ровно `scope`; тело — JSON `{"allow": [...], "deny": [...]}`
(оба ключа обязательны; отсутствующий трактуется как пустой список + WARNING).
Glob-семантика: `*` — любая последовательность символов **без** `/`; `?` — ровно
один символ кроме `/`; `[abc]`/`[a-z]`/`[!abc]` — класс; `**` целым компонентом —
ноль или более компонентов (`a/**` покрывает и сам `a`, и всё под ним).
Абсолютные пути, `~`, `\`, сегменты `..`, пустые строки делают ограду
невалидной (она считается отсутствующей: ERROR в `docs-lint`, мандата нет);
пустой `allow` — WARNING. Правка спеки (в том числе ограды) меняет хеш и
**инвалидирует approval** — требуется переодобрение человеком.

```scope
{
  "allow": ["tools/<task>/**"],
  "deny": ["docs/**", "src/**", "tests/**"]
}
```

## Approval (одобряет только человек)

<!-- Агент НЕ вправе перевести спеку в approved самостоятельно. -->

Одобрение — **исключительно человеческое** действие: `~/.config/opencode/bin/spec-approve <spec>`
либо `/spec-approve <spec>` в TUI. Агент не пишет артефакт одобрения сам и не
имеет права менять статусную строку на `approved`.

Валидное одобрение (`spec-approve`) — это:
1. флип статусной строки спеки на `approved`;
2. штамп `- **Утверждено:** <ISO8601> (human)`;
3. хеш (sha256) **пост-флип** содержимого спеки;
4. запись `approvals/<sha256(корня)[:16]>/<sha256(пути спеки)[:16]>-<slug>.json`.

Правка спеки после одобрения меняет хеш и **инвалидирует approval** — требуется
переодобрение человеком.
