- **Дата:** 2026-10-02
- **Метод:** перекрёстный аудит — `@explorer` (фактическая карта кода и дрейфа), `@oracle` (состязательный аудит готовности и риска), плюс независимая локальная проверка оркестратора (прогон команд).
- **Область:** `/home/asdcxfrt/Projects/spec-gate-kit` на ревизии `f984997`; производное состояние — `evidence-atomic-p0` = `DONE`, `gate-parity-p0` = `DONE`, `audit-chain-p0` = `draft` (не одобрен), `preflight-0` — в архиве.
- **Рабочая гипотеза, которую аудит проверял:** кит — переносимый drop-in механики Zero-Code Gate. Аудит её **не подтвердил** в текущем виде.

## 1. Вердикт готовности

> **НЕ ГОТОВ заявляться переносимым deliverable. Готов «с условиями» (ready-with-conditions) после одного сфокусированного P0-спринта.**

Ядро принуждения — решение гейта, паритет TS↔Python по `scope`/glob, атомарная запись evidence с foreign-guard, выводимое состояние без второго хранилища — **реально и корректно**, честно задокументировано как soft guardrail. Но кит проваливает переносимость «в лоб»:

- **Одиночный главный блокер (F1):** два pytest-файла хардкодят живой путь автора `/home/asdcxfrt/.config/opencode/bin/...`, поэтому документированная процедура проверки после установки тестирует **живую конфигурацию автора**, а не кит. Любое заявление о верификации для нового владельца обнуляется.
- **F2:** Stage-1 харденинг доверия (README §5-P0.1) **не реализован** в отгружаемом JSON: `~/.config/opencode/**` остаётся агенту доступным, а строковая форма `"bash": "allow"` у трёх агентов разворачивается в `{"*": "allow"}` и обнуляет глобальные `deny`.
- **F3:** титульный README фактуально устарел и местами **ложен** (см. §4).

Без F1–F3 метка «portable v0.1» была бы нечестной.

## 3. Что подтверждено (сильные стороны, найденные независимо)

Аудит **не нашёл** дефектов в следующем (проверено обеими сторонами):

1. **Паритет TS↔Python по `scope`/glob** — `globSource`/`glob_regex`, `scopeAllows`/`scope_allows`, валидация паттернов и правило «`deny` побеждает `allow` при объединении мандатов» совпадают построчно (`config/plugins/spec-gate.ts:695-711`, `config/bin/spec_scope.py:309-376`; `glob_match` — `:365-367`, `scope_allows` — `:370-376`); якорь `(?![\s\S])` корректно обобщает `re.fullmatch`. Векторы `config/tools/gov/scope_vectors.json` (20 pattern + 5 scope) гоняются в обоих рантаймах.
2. **Порядок решения гейта** совпадает с доктриной: kill → allowlist → извлечение целей → exempt → `.slim/spec` → `docs/**` refuse → `.serena` → `GATE-OFF` → мандат (`spec-gate.ts:805-864` против `config/AGENTS.md:51-80`).
3. **`docs/**` закрыт безусловно**, включая serena-писателей и базовый путь (`docsBlocked:213-216`).
4. **Evidence v2 честен:** `dod-run` пишет atomic + readback + fail-loud на чужой `spec_sha256` (exit 3, файл не тронут); `spec-status` считает `DONE` ровно по инварианту
   $$\text{DONE} \iff \forall\,\text{check}:\ \bigl(\text{exit}=0 \;\land\; \text{spec\_sha256}_{\text{ev}} = \text{spec\_sha256}_{\text{now}} \;\land\; \text{git\_head}_{\text{ev}} = \text{HEAD} \;\land\; \lnot\,\text{tree\_dirty}\bigr)$$
   (`spec-status:206-227`); `spec-revoke` bare-token fix на месте; `docs-lint` ловит коллизии `dod.id` и внутри спеки, и между контрактами.
5. **На текущей ревизии evidence не подделано на диске:** у обеих одобренных спек текущий `sha256` == записанный `spec_sha256`, `git_head == HEAD == f984997`, записано `tree_dirty=false`.

## 5. Ответы на ключевые вопросы

**`tree_dirty` — дыра?** Нет. Исключение `.slim/spec` (вход жизненного цикла) и `verify/` (артефакт самого прогона) **необходимо** — иначе собственные выходы `dod-run` самоинвалидировали бы `DONE`. Скрыть реальную грязь оно не может: изменённые/untracked исходники по-прежнему дают `dirty`. Остаточный риск смежный и уже задокументирован: `verify/*.json` руками редактируем (`exit_code` переключается при целом `spec_sha256`, т.к. хеш покрывает спеку, а не evidence), и `tree_dirty` этого не поймает — это проблема **неподписанного evidence**, а не `tree_dirty`. Правка — только формулировка вывода (F13).

**Целостность evidence.** Путь записи честен (atomic + readback + fail-loud, exit 3, файл не тронут). Плоский стор больше не «молча клинит», а **громко отказывает**, а `docs-lint` служит pre-approval заслоном. Политика стора — **рассогласована** (F8). Аудитор рекомендует для кита **tracked-proof** (самодостаточно, без второго хранилища, совпадает с кодом и `.gitignore`), а shallow-планирование — только как платную опцию по M4, не как дефолт. Это решение человека.

**`audit-chain-p0`.** Дизайн звучит (inline-цепь, `GENESIS`/`DETACHED`, ленивый boot-canary включая kill-switch, fork-tolerant `audit-verify` 0/1/2, vectors-first) и совместим с GOV-2/GOV-4/ADR-0003. **Но к одобрению не готов без правок**: (1) F6 — правило формата чисел; (2) F7 — строка про kill-switch в доктрину; (3) F15 — назвать env-переменную переопределения журнала; (4) зафиксировать fail-open при провале хеша `plugin` на импорте. Отсутствие `audit-verify`/векторов — **не** блокер: DoD черновика описывает работу под мандатом (см. примечания §4). Пересечение `scope` с активным `gate-parity-p0` объединяется безвредно (WARN), но гигиена single-writer требует архивировать завершённые контракты (GOV-6).

**Тесты.** TS-харнесс достоверен: 20/20 зелёных за 0.62 с, покрывает allow/block/`deny`-wins/isolation/векторы, с честной оговоркой — регистрация v2-хуков замокана (тест 14), нужен Node ≥ 22. `test_scope_parity.py` образцовый (берёт реальный матчер и пути относительно файла). **Void:** F1 (два файла тестируют живую машину) и F4 (нет `spec-status`/`spec-new`/`gate-off`; `wave-run --execute` не доказан на реальном `dod-run`).

**Переносимость.** Не drop-in. Машинная связанность: `/home/asdcxfrt` в 7+ местах (`config/opencode.json:10,323`, промпты slim-json ×3, `AGENTS.md:375-380`, `config/command/spec-approve.md:9`, 2 test-файла, `spec-new:170`), `~`-пути в `external_directory`, 20× `opencode-go/*`, абсолютные `spec`-пути во всём evidence. README §4 должен стать чек-листом подстановок с точными `file:line`.

## 7. План дальнейшей разработки

### 7.1. Перед меткой «portable v0.1» (P0-спринт; всё мелкое, всё блокирует метку)

Порядок зависимый — сверху вниз:

0. **Мандат спринта (только человек).** Ни один шаг ниже невозможен без активного одобренного контракта (или scope-амендмента), покрывающего `config/bin/tests/**`, `config/*.json`, `README.md`, `config/templates/**`, `VERSION`/`install.sh`, `examples/**` — сейчас эти пути не покрыты ни одним мандатом, поэтому любой агентский write получит `[SPEC-GATE BLOCKED]`.
1. **F1 — параметризовать пути тестов** (`BIN = Path(__file__).parents`), как уже сделано в `test_scope_parity.py:31-34`; прогнать сьют из чистого `$HOME`. → снимет главный блокер.
2. **F4 — тесты на дыры:** `spec-status` (все переходы `INTAKE→DONE` и stale-ветки), `spec-new` (скаффолд в tmp), `gate-off`/`gate-on` (маркер + взаимодействие с гейтом), `wave-run --execute` на реальном `dod-run`.
3. **F2-minimal — Stage-1 в отгружаемом JSON:** убрать `~/.config/opencode/**` (и `~/.local/share/opencode/**`) из `external_directory`; заменить строковые `bash: "allow"` на объектные карты у трёх агентов так, чтобы в них **не** попадали человеческие CLI (`spec-approve`, `spec-revoke`, `gate-off`, `gate-on`). Точка закрытия — именно `bash`-карта, а не allowlist: в `READ_ONLY_TOOLS` этих CLI никогда не было (`spec-gate.ts:63-86`). (= README P0.1 + `SYNTHESIS P0.6`.)
4. **F3 — переписать README** (§1 инвентарь, §3 процедура установки, §4 чек-лист подстановок с `file:line`, §5 статусы) + пометить `SYNCED: <rev>`.
5. **F10-minimal — упаковка:** `VERSION`, `install.sh --target DIR` (проверка Python ≥ 3.11 / Node ≥ 22, бэкап существующего конфига, drop-in, смоук `INTAKE→DONE` в tmp), CI-джоб (`pytest` из чистого `$HOME`, `node --test`, scope-parity, smoke).
6. **F8 — решить политику `verify/**`** (рекомендация аудитора: tracked-proof; тогда поправить `SYNTHESIS §3a`). Решение человека.
7. **F16 + F12 + F19 — гигиена кита:** централизовать `find_root`/`resolve_target`/`spec_rel`/`dod`-парсеры в `spec_scope.py`; исправить шаблон (`tools/<task_slug>/**`, slug-префикс `dod.id`, раздел R6/evidence-v2, канонические команды); наполнить `examples/`.
