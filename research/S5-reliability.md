## 1. Failure-mode taxonomy

| # | Mode | Detection signal | Mitigation | Recovery / rollback | Residual risk |
|---|---|---|---|---|---|
| F1 | **Silent no-op gate** — plugin not loaded, stale `config/` snapshot, `OPENCODE_SPEC_GATE=off` set, or `findRoot` miss (`.git` stop, `$HOME` stop, symlinked root). Gate returns before parse with no audit (`spec-gate.ts:194-206,803`). | Canary: every wave starts with intentional blocked-write probe expecting `[SPEC-GATE BLOCKED]`; `spec-status` reports `worktree.head/dirty`; audit volume drops to 0. | Fail-loud boot check (`install.sh` smoke: `INTAKE→DONE` in tmp dir, `README.md:111-118`); pin plugin `id` + version; canonicalize both sides of `specDir` compare (audit §2.8). | `rm plugins/spec-gate.ts` + restart is the documented rollback (`SPEC-OpenCode-Hardening.md:457-460`); re-run canary before resuming waves. | Kill switch is global and unaudited by design — any process-env writer defeats all detection. |
| F2 | **Tamperable approvals** — record is `{spec, spec_sha256, approved_by:"human"}` with no signature (`docs/adr/0002:26-28`); agent with `bash` writes `~/.local/share/opencode/approvals/**` (exempt, `spec-gate.ts:179-187`). | `spec-approve` readback assert (`notes/2026-09-28…:P2-13`); cross-check `approved_at` vs human session log; `git status` of spec vs record `spec_sha256`. | HMAC/GPG-sign records with key outside agent reach, or UID-split approver; remove approvals/audit from agent `external_directory` (`README.md:§5.P0.1`). | `spec-revoke --all` + human re-approve; treat all `DONE`s since suspected forgery as `VERIFY`. | Without kernel identity, `approved_by` stays a string; signing only moves trust to key custody. |
| F3 | **Tamperable audit log** — `audit()` is append-only `JSONL` with `mkdir+appendFileSync`, fail-open on error (`spec-gate.ts:788-795`); no `prev_hash`; agent-exempt path. | Log-gap detector: monotonic `ts` + per-`sessionID` sequence breaks; `allowed` without preceding `approved` record. | Hash-chain ($H_n = \operatorname{sha256}(H_{n-1} \\| \text{entry}_n)$) + append-only store or remote shipper; audit failure → `stderr` today, should → alert. | No rollback possible — log is evidence, not state; fork a new chain, annotate compromise window. | Local chain still rewritable by whoever owns the file; tamper-*evident*, never tamper-*proof* without external anchor. |
| F4 | **Non-atomic evidence writes** — `dod-run:319-325` does `mkdir+write_text`; kill/parallel race → torn JSON → `spec-status:189-192` reads as absent (`repo-audit:§2.5`). | `json.load` failure rate on `verify/*.json`; `dod-run` overlapping PIDs; `tree_dirty` flaps. | Reuse `spec_scope.atomic_write` (same-dir tmp + `os.replace`) + readback, per audit P1-2; per-spec namespaced store `verify/<slug>/<id>.json` (note `dod-run-flat-store-collision.md:64-74`). | Delete torn files, re-run `dod-run --only <id>`; `docs-lint` already errors on cross-contract `id` collision — keep it. | `os.replace` is atomic per-file, not per-wave; crash mid-wave still yields partial `VERIFY` set (see F10). |
| F5 | **Denylist theater** — `dod-run:68-78` blocks substrings (`sudo`, `dd if=`, `rm -rf /`, `:(){`) but passes `dd of=/dev/sda`, `rm -rf /*`, `rm -rf $HOME`, `python -c 'os.system(…)'` (`repo-audit:§2.4`). `bash` allowlist `python -m *` bypasses `edit` entirely (`SPEC-OpenCode-Hardening.md:365-367`). | Refused-command log review; red-team vector suite (`tools/gov/scope_vectors.json` missing — `repo-audit:§2.3`). | Document denylist as typo-guard only; real confinement = `permission.bash` deny + object-form maps (never string `"allow"`, `README.md:§5.P0.1`) → oclab seccomp/net profiles. | Revoke + `git checkout` affected paths; audit which `dod` command ran where. | Shell-string analysis is an arms race (quoting, `$(…)`, heredoc, env-obfuscation — `adr/0001:86`); never HARD via pattern list. |
| F6 | **Flaky / duplicated tests as DoD** — 155 checks/wave, ~75–80% duplicates (`pytest` 14×, `ruff` 15×, `README.md:§5.P1.5`); flaky green → false `DONE`. | Per-check `duration_s` variance + `tail` inspection; re-run stability (`--only` twice); `exit_code==0` with `stale==true` masked as pass. | Deduplicate `dod` fences (one owner per full suite); `--fail-fast`, quarantine flaky ids, require $n \ge 2$ consecutive passes for flagged checks; record `timeout:true + exit 124` distinctly (`spec-driven-development.md:634`). | Mark check `stale`, re-run wave subset (`dod-run --changed` proposal, `README.md:§5.P0.4`); never hand-edit `verify/*.json`. | Statistical `DONE` (e.g. $P(\text{false DONE}) \le 10^{-3}$) needs a test-reliability model the kit has no data for. |
| F7 | **Port / env conflicts in parallel waves** — e2e/ctest stands collide; laptop throttle (`loadavg 26.68` on 6 cores, `AGENTS.md` caveats) turns parallelism into flakes. | `EADDRINUSE`, bind-retry storms; `ctest -j1` vs `cmake -j$(nproc)` violations in audit. | Wave parallelism cap 2–3 contracts, port lockfile, core pinning (`nice/taskset/ionice`), `ctest -j1`, single full-suite owner (`README.md:§5.P1.5`). | Kill wave, release locks, serialize remainder; `tree_dirty` reset via `git stash` discipline. | File locks don't survive `kill -9` reliably; needs kernel cgroup + netns ownership (oclab). |
| F8 | **Context blowup / truncation** — orchestrator sees whole context; long tails (`tail` ~2000 chars, `adr/0004:82`) + 40-evidence waves overflow → dropped `deny` or `scope` misread. | Token accounting (`oc-usage` from `opencode.db`, `SPEC-OpenCode-Hardening.md:§16.5`); `scope_report` warnings ignored rate. | Evidence-plan before implementation (`verification-planning` skill); `--json` machine outputs, `tail` caps, per-contract status sharding; council only for high-stakes. | Resume from derived state (`spec-status` recomputes; no `state.json` by design, `adr/0003`) — re-emit narrowed prompt. | No platform token budget enforcement exists; SOFT convention only. |
| F9 | **Hallucinated "done"** — agent declares DONE without artifacts. Kit's structural answer: $$\text{DONE} \iff \text{valid-approval} \wedge \forall c \in \text{DoD}: (\text{exit}_c = 0 \wedge \text{sha}_c = \operatorname{sha256}(\text{spec}) \wedge \text{head}_c = \text{HEAD} \wedge \neg\text{dirty}_c)$$ (`spec-status:199-212`, `README.md:81-86`). | `spec-status` is read-only derived state; any claim without matching `verify/<id>.json` triple is `APPROVED`/`VERIFY`, never `DONE` (acceptance table `SPEC-OpenCode-Hardening.md:426-445`). | Keep state derived, never stored (`adr/0003`); forbid human-editable status files; `docs-lint` requires real ADR links + existing `docs/…` paths. | Re-run `dod-run` after committing (`tree_dirty=false` precondition, `spec-driven-development.md:641-646`). | `DONE` attests *the checks ran green on this revision*, not that the checks were the right checks — spec quality stays human-gated. |
| F10 | **Stale evidence by revision** — global staleness: *any* commit invalidates *all* evidence ($$\text{stale} = (\text{ev\_head} \neq \text{HEAD}) \vee \text{tree\_dirty}$$, `README.md:85`); full wave ~14 min/16 contracts. Plus flat-store collision: two specs sharing `id` overwrite `verify/<id>.json`, loser stuck in `VERIFY` (`notes/dod-run-flat-store-collision.md:8-15`). | Per-check `stale` flag + `worktree.head/dirty` in `spec-status --json`; duplicate-`id` lint ERROR. | Surface staleness: invalidate only when `scope.allow` files changed + `dod-run --changed`; namespaced store with flat fallback; fail-loud on foreign-`spec_sha256` overwrite. | Re-approve (hash rule) + targeted re-run; orphaned `verify/*.json` GC after rename. | Finer staleness weakens the "one mental model" invariant (`repo-audit:§5`); needs explicit policy choice (`README.md:§5.P1.7`: untracked vs tracked vs artifact-store). |
| F11 | **Partial / crashed waves** — multi-target `allowed` audit records only first root (`repo-audit` NIT, `spec-gate.ts:847-858`); no wave transaction id; orchestrator background lanes (`task_*`) resume blind. | Wave manifest (expected `id` set) vs present `verify/*.json`; orphan `started_at` without `finished_at`. | Wave id in every evidence record; idempotent `run_check`; `--only` resume; `R6` policy-line (stop after 3 consecutive failures, count from audit journal, never a counter file — `AGENTS.md` R6). | Resume with `--only` missing ids; `spec-revoke` single-spec semantics (audit found `revoke` wiped whole dir — `notes/spec-approve-hardening:§4`, now fixed to per-spec delete). | At-least-once execution without exactly-once store: duplicate side-effecting checks need their own idempotence. |
| F12 | **Prompt-injection via repo content** — `docs/**`, issues, test fixtures, webfetch results are untrusted; agent with `bash` + exempt config paths can be steered into self-approval or exfil. | `docs-immutable` (`GOV-2`, `spec-gate.ts:676-708`) violations attempted; `/spec-approve` shell-block provenance (client-executed, `AGENTS.md`). | Treat all repo/web content as data: read-only allowlist stays exhaustive; human-only CLIs off `$PATH` and off bash-allowlist (`adr/0002:39-44`); `docs/**` closed even to `GATE-OFF` and kill-switch-less paths. | Quarantine + human review of suspect spec text; `spec-revoke` + re-author. | Convention-level only: no sandbox, no egress filter, `relative_path` root-confusion (`SPEC-OpenCode-Hardening.md:375-376`) persist until oclab. |

## 2. Detection & observability (what to watch)

1. **Audit journal as primary sensor.** Every gated verdict → `~/.local/share/opencode/audit/spec-gate.jsonl` (`spec-gate.ts:834-858`), fail-open on write error (`:788-795`). Alert on: volume collapse (gate off / bypass via `bash`), `reason` histogram drift (`no-mandate` spike = missing scopes; `deny:*` spike = scope fight), multi-root `allowed` undercount (known bug). Missing `tools/gov/scope_vectors.json` means TS↔Python glob parity is *unobserved* — build the vector suite first (`repo-audit:§2.3`).
2. **Derived state as ground truth.** `spec-status --json` per contract: `hash_matches`, `exit`, `stale`, `git_head`, `tree_dirty` (`spec-status:172-212,277-279`). Dashboard rule: `DONE` iff zero stale + zero missing; `VERIFY` with all-present-but-stale = revision drift, not test failure — route to re-run, not debug.
3. **Canaries and red-team probes.** Boot canary (blocked write without approval), nightly denylist-bypass probes (F5 forms), harness isolation check (TS tests must use `--approvals-dir` tmp, never real store — `repo-audit:§2.CRITICAL.1-2`). Stale harness currently *lies green*: `spec-gate.test.ts:46-51,116-119` assert obsolete CLI output and scopeless-allow (`repo-audit:§2.1`).
4. **Cost/context telemetry.** `oc-usage` reads `opencode.db:session_message` (`SPEC-OpenCode-Hardening.md:397-424`); track per-agent tokens, `tail` truncation rate, wave wall-time (baseline ~14 min/16 contracts).

## 3. HARD-vs-SOFT design rule

Spec `§3/§6` states the invariant: *everything unconditional must be HARD; SOFT is heuristics only* (`SPEC-OpenCode-Hardening.md:50-56,111-132`). Reality check from audit:

- **HARD today (platform-enforced):** `permission.external_directory` deny+allow, per-agent `edit`/`bash` maps, plugin `throw` on file-tool paths, `docs-immutable` *for file tools*, hash-tied approvals/evidence. Keep here: path-confinement of file tools, `deny`-wins-union mandate, derived-state math, `id`-uniqueness lint as ERROR.
- **SOFT masquerading as HARD (demote or harden):** `§8` per-agent path-scoping was never implemented (`repo-audit:§1.3` — fixer has no block, experts have blanket allow); `§10` model map drifted from JSON (`repo-audit:§1.4`); `dod` denylist (F5); audit integrity (F3); `docs/**` vs `bash`/MCP-root confusion (F12). Rule: **if the agent's toolset contains a writer the enforcer cannot see (`bash`, `spec-new`/`dod-run` shell paths, `python -m *`, serena `relative_path`), the property is SOFT — label it so** (`SPEC-OpenCode-Hardening.md:379-381`).
- **Decision test:** a requirement graduates to HARD iff (a) enforced below the agent's privilege level (platform hook with no bypass path, or kernel), (b) covered by a failing-closed test that runs in CI, (c) its bypass is observable in the audit log. Else it stays SOFT with an owner, a lint, and a dashboard — never a promise.

## 4. Attestation / provenance design (minimal, compatible)

Records today: approvals `{root, spec, spec_sha256, …}` (`adr/0002:28`), evidence v2 `{check, cmd, exit_code, spec_sha256, tail, git_head, tree_dirty, scope_sha256, …}` (`spec-driven-development.md:621-635`), audit `{ts, sessionID, tool, targets, root, decision, reason, spec}` (`spec-gate.ts:773-782`; ADR text lags — `repo-audit:§2.10`). Proposal preserving readers (match on `spec`+`spec_sha256`, filename insignificant — `notes/spec-approve-hardening:§7`):

1. **Sign approvals:** `sig = \operatorname{Sign}_{k_{human}}(\text{root} \\| \text{spec} \\| \text{spec\_sha256} \\| \text{approved\_at})$`, Ed25519/GPG, pubkey pinned in repo, private key off-agent (passphrase-held or UID-split approver). `approvalScan` verifies before granting; unsigned → `inactive-spec`. Keep `flip-before-hash` order (`adr/0002:33-38`).
2. **Hash-chain audit:** each line adds `prev_hash, entry_hash` with $$H_0 = 0,\quad H_{n} = \operatorname{sha256}(H_{n-1} \,\|\, \text{canonical\_json}(entry_n)),$$ shipped to append-only sink; verifier replays chain offline. Local-only chain = tamper-evident, not tamper-proof — document as such (`README.md:§5.P0.8`).
3. **Evidence binding:** extend v2 with `wave_id, approver_sig_ref, chain_head`; `spec-status` checks signature ref + freshness triple. Torn-write protection via atomic write + readback (`notes/spec-approve-hardening:P2-12/13`). Namespaced paths `verify/<slug>/<id>.json` with flat fallback; writer refuses foreign-`spec_sha256` overwrite (fail-loud).
4. **Non-goals:** no PKI beyond one human key per machine; no confidential fields (logs stay reviewable); approval locality (per-machine, non-committed) retained (`adr/0002:63-65`).

## 5. Trust-boundary roadmap (toward oclab kernel isolation)

`SPEC-OpenCode-Hardening.md:§11` defers hard isolation to oclab; `spec-driven-development.md:826-830` names `bwrap --ro-bind` + `EROFS` as the real read-only barrier. Migration in three cuts, workflow unchanged:

- **Stage 1 — close self-modification (no kernel):** remove `~/.config/opencode/**` + approvals/audit from agent `external_directory`; object-form `bash` maps only, never string `"allow"`; human CLIs off allowlist; fix `specDir` canonicalization + `~`-as-leading-only + third-fence-parser dedup (`repo-audit:§2.8/11/12/15`). Cost: agent can no longer self-service its config — accept explicitly (Step 2 was *deliberately deferred*, `SPEC-OpenCode-Hardening.md:259`).
- **Stage 2 — attestation without kernel:** ship §4 signing + hash-chained audit + atomic namespaced evidence; gate boot canary; `scope_vectors.json` parity CI. This is the auditability ceiling of pure-userspace enforcement.
- **Stage 3 — oclab (`bwrap --ro-bind`, uid-split, network profiles):** workspace mounted RW only inside `scope.allow`; `docs/**`, config, approvals, audit → `ro-bind` (`EROFS`); approver UID ≠ agent UID; `dns-only`/no-net profiles per lane; MCP socket passthrough allowlist (serena/jupyter/memory need explicit forwarding — known blocker list `SPEC-OpenCode-Hardening.md:243-249`, incl. `resolv.conf` symlink bug, `permission` plural typo, RO-`.opencode` manifest move). spec-gate remains as friction/audit layer above the kernel boundary — defense in depth, not replacement (`SPEC-OpenCode-Hardening.md:234`).

## 6. Minimal viable reliability posture (if only six things)

1. Boot canary + `OPENCODE_SPEC_GATE` provenance alert (kills F1 silence).
2. Approvals/audit/config out of agent reach + object-form `bash` maps (shrinks F2/F3/F12 blast radius to kernel-track).
3. Atomic, namespaced, readback-verified evidence + `id`-collision ERROR kept (fixes F4 + F10-collision).
4. Denylist relabeled typo-guard; destructive protection owned by `permission.bash` deny (stops F5 theater).
5. Derived-state dashboard (`hash/exit/stale/head/dirty` per check) + wave manifest with `wave_id` and `--only` resume + R6-from-audit (contains F6–F11).
6. Hash-chained audit + signed approvals (Stage 2 attestation; makes F2/F3 *evident* while awaiting oclab).

4. Do we cap `tail`/evidence size formally (2000 chars today, `adr/0004:82`) vs full-log external refs for long builds?
5. Flaky-check policy: quarantine list, $n$-consecutive-pass rule, or statistical `DONE` threshold — what $n$, what $P(\text{false DONE})$?
6. oclab trigger: which residual bypass (bash-heredoc, `relative_path` confusion, MCP exfil) forces Stage 3, and who owns the `bwrap`/uid-split patches?
7. Parallel-wave safety: lockfile + port registry in userspace, or wait for netns/cgroup ownership?
