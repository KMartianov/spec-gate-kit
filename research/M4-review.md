## 3. Подозрения на баги (`sim.py:строка`), материальность

1. **Материален. `metrics:671`.** `false_detect` = `defect[c] and not detected[c]`: дефект, пойманный один раз, но не починенный ($1-p_{fix}=15\%$) и пропущенный при переверификации, **не считается** ложным DONE. Систематическое занижение $P(\text{false DONE})$ для всех политик; сильнее бьёт по A/B (больше реранов → больше таких исходов).
2. **Материален. `_dispatch_verify:448–453` + `_on_verify:481–485`.** Дедуп даёт `suite_credit=True` всем контрактам даром: один общий suite-ран детектирует дефект **каждого** контракта с полным $d_{suite}=0.8$. Утверждение «B сохраняет риск A» держится на допущении идеального переноса детекта; при деградации переноса риск B растёт. Не баг кода, а нагрузочное допущение без свипа.
3. **Материален. `_maybe_start_wave:419–420`.** Волна стартует лишь при полном простое light-слотов: verify никогда не перекрывается с draft/impl. Раздувает все wall, но сильнее штрафует многоволновые A/D — т.е. увеличивает дельту A→B. Абсолютные минуты тем самым завышены структурно.
4. **Порочная метрика (не баг, а ловушка). Стоимость/реворк.** `$` определяется draft/impl/rework ($0.117/0.056/0.035$), чек — $\$0.0012$: ранжирование по `$` почти не чувствует верификацию. Хуже: `B+C+D+E` «самый дешёвый» ($\$5.25$, rework $3.7$ vs $5.5$) **потому что пропускает дефекты** и не чинит их. E-first-pass $83.1\%$ «лучше» A по той же причине (меньше чеков — меньше observed fails). M2 это не подсвечивает.
5. Нематериален. `_pct:732–737` — квантиль через `round()` вместо интерполяции; сдвиг общий для всех, ранжирование не трогает.
6. Нематериален. `_on_retry:539` — ретрай при дедупе заново крутит suite (`suites++`); лёгкая инфляция suites B. На выводы не влияет (suites B $6.5$ vs A $73.6$).

## 4. Что дисконтировать с учётом M3 (R1–R17, E1–E16)

- **Абсолютные минуты (203/250 и т.п.) — дисконтировать целиком.** Доминируют неприорные draft/impl/rework ($12/8/4$–$5$ мин, priors) + структурная сериализация п.3; M3 не измеряет ни $S_a$, ни $p_{defect}$, ни flake (R3: вся сохранённая эвиденция зелёная — first-pass неизмерим). M2 это заявляет (§7), держать за слово.
- **«Дедуп $-65\%$ heavy $\approx$ M3 R9 $-63\%$» — совпадение частично случайное.** R9 — single-wave срез команд; $-65.2\%$ в симуляции включает эффект re-wave (A: $73.6$ suite-ранов vs B: $6.5$). Направление верно, величину так калибровать нельзя; плюс M1 ждал $u=0.20$–$0.25$, модель дала $u=0.32$.
- **Профиль чеков в модели двухклассовый** (suite $39$ с + local $1.8$ с) против измеренного R1/R10 (медиана $0.74$ с, p99 $53.3$ с, max $464.9$ с, asan-стенд $\sim190$ с). Хвосты отсутствуют — p95 wall недооценён; моя ячейка heavy-profile показывает, что при asan-доминировании выводы про H=2 меняются количественно.
- **$P(\text{false DONE})$ $1$–$2\%$ — нижняя граница** (занижение п.1 + идеальный перенос п.2 + $p_{hidden}=0.005$ без данных; M1 Q1 открыт). Порядки для сравнения годны, пороги для решений — нет.
- **Одно измерение, которое сильнее всего снимет неопределённость:** распределение латентности человека $S_a$ + эффект `--all` (свип approval_slow уже показал: A $622$ vs B $233$ мин — человек, а не CPU, главный рычаг), вторым — $p_{hidden}$ (границы: hidden $0\to2\%$ двигает лж-DONE B+C $1.9\%\to4.0\%$).

## 5. Итоговая позиция по H1–H7

- **H1 (дедуп): держится.** Suites $73.6\to6.5$, heavy $-65.2\%$, ранжирование стабильно по всем свипам; величина зависит от профиля (suite-cheap: выигрыш $13$ мин вместо $43$).
- **H2 (shallow): отвергнута как сформулирована** ($\Delta P\approx0$ ложно даже в симуляции: $+1.1$ п.п., из них shallow $0.44$ п.п. + потеря детекта). Допустима лишь ослабленная версия «C экономит $\sim3$ мин за $+1$–$2$ п.п. риска при неизвестном $p_{hidden}$».
- **H3 (параллелизм): отвергнута при базовых приорах, условна в общем.** Проигрыш — артефакт контеншна $\times1.3/\times2$; без него B+D выигрывает. B+C+D не выигрывает ни в одной ячейке — «фабрику» нельзя рекомендовать без новых данных.
- **H4 (сэмплинг): отвергнута.** При калиброванных приорах $10^{-3}$ недостижим ни при каком полезном $s$; достижим лишь при $\approx$идеальном детекте (ячейка G), которого M3 не подтверждает.
- **H5 (pre-lint/батч): держится.** `19.3→5.9` взаимодействий при том же wall; при медленном человеке — единственное спасение ($622\to233$ мин). Единственный вывод, устойчивый ко всем свипам.
- **H6 (изоляция): вне модели** (M2 §1, честно). Симулятор о ней ничего не говорит; single-writer/состязание — параметризация, а не измерение.
- **H7 (экономика): отвергнута как метрика ранжирования.** `$` не различает политики осмысленно (все $\$5.2$–$\$5.9$, движимы реворком) и извращённо награждает пропуск дефектов. Для решений использовать wall/human/риск, не `$`.

**Одна строка:** из M2 уцеливают дедуп (B), батч-approve (H5) и запрет агрессивного сэмплирования; shallow (C) — платная опция $3$ мин за $+1$–$2$ п.п. риска, а не бесплатный выигрыш; H=2 — только после замера контеншна и при тяжёлом asan-профиле; «фабрика» B+C+D currently не оправдана ни одним прогоном.
