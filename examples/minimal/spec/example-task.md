## Раздел 1. Цели и границы (Scope)

### Цели
- Показать машиночитаемый мандат записи (`scope`) и DoD-контур (`dod`).

### Non-goals (категорически запрещено менять)
- Код кита: пример ничего в нём не меняет.
- `docs/**`: human-owned зона (GOV-2), агент её не трогает.

## Раздел 2. Архитектурное решение (Mini-ADR)

- **Контекст и проблема:** нужен эталон контракта для принимающей машины.
- **Принятое решение:** один файл-контракт со slug-префиксными `dod.id`.
  - Базовый ADR: `docs/adr/0001-gate-as-soft-guardrail.md`
- **Отвергнутые альтернативы:**
  - Альтернатива A — бесслаг-овые `id` (`build`/`test`): коллизия в плоском
    `verify/<id>.json` между контрактами; отклонено (`docs-lint` ERROR `dod-duplicate`).

## Раздел 3. Спецификация контрактов и интерфейсов (Reference)

### Ограждение `scope` — машинный мандат записи (GOV-1)

```scope
{
  "allow": ["tools/example-task/**"],
  "deny": ["docs/**", "config/command/**", "**/approvals/**", "**/audit/**"]
}
```

### Математический инвариант (строго LaTeX)

$$\operatorname{mandate}(p) \;=\; \bigl(\exists\,a \in \mathrm{allow}:\ a \Rightarrow p\bigr)\ \land\ \neg\bigl(\exists\,d \in \mathrm{deny}:\ d \Rightarrow p\bigr)$$

## Раздел 4. Evidence Path (план доказательства корректности)

- **Стратегия:** `verification-planning`
- Чеки-заглушки (`true`): цель примера — форма контракта, а не вычисление.

## Раздел 5. Definition of Done (чек-лист)

- [ ] `scope`-фенс валиден и покрывает изменяемые пути (без мандата запись запрещена).
- [ ] `id` каждого `dod`-чека префиксен slug-ом `example-task`.

```dod

  "checks": [
    {"id": "example-task-build", "cmd": "true"},
    {"id": "example-task-test", "cmd": "true"}
  ]

```
