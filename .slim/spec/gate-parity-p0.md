## Раздел 1. Цели и границы (Scope)

### 1.1 Зачем

Семантика `scope` реализована **дважды**: в рантайме — на TypeScript (`config/plugins/spec-gate.ts`), и в Python (`config/bin/spec_scope.py`), которым пользуются все CLI, включая предполётный линт. Доктрина объявляет таблицу векторов единственным источником правды (`config/bin/spec_scope.py:6-8`), но **файла векторов не существует** — механизма, который поймал бы расхождение, нет.

Recon `exp-4` нашёл три конкретных дефекта:

1. **Гипотеза о расхождении анкоринга — ПРОВЕРЕНА И НЕ ПОДТВЕРДИЛАСЬ.** Recon `exp-4` предположил, что TS `globMatch` (`config/plugins/spec-gate.ts:469-475`) пере-разрешает путь с завершающим `\n`, потому что в JS `$` матчит перед завершающим переводом строки, тогда как Python использует `re.fullmatch` (`config/bin/spec_scope.py:365-367`). Прямая проверка на Node v26.10.0 это опровергла: **без флага `m` символ `$` — строгое утверждение конца входа** (`/^src\/[^/]*\.ts$/.test("src/app.ts\n") === false`), мягкое поведение даёт только флаг `m` (или Python `re.match` вместо `fullmatch`). Расхождение не воспроизводится: обе стороны уже отвергают завершающий `\n`, и случай №17 (§3.1) зелёный на обеих. Требование к TS поэтому скорректировано до **флаг-независимой** записи якоря: сегодня она не меняет наблюдаемого поведения, но исключает регрессию, если якорь когда-нибудь получит флаг `m`.
2. **Сравнивать надо результат, а не строку регэкспа.** Python `re.escape` (`spec_scope.py:355`) экранирует больше символов, чем TS `escapeRegExp` (`spec-gate.ts:410-411`), поэтому строки `glob_regex` и `globSource` **не равны** при эквивалентной семантике. Паритет обязан проверяться по результату матча на таблице случаев.
3. **TS-харнесс лжёт зелёным.** `config/plugins/__tests__/spec-gate.test.ts` (242 строки) вызывает `spec-approve` **без `--approvals-dir`** (`:46-51`) и пишет в реальный `~/.local/share/opencode/approvals/**`, а `after()` чистит каталоги, спарсенные из вывода, которого больше нет (ассерт `out.endsWith(".json")` устарел: CLI печатает `approved <spec> (sha256 …)`). Фикстурная спека не содержит `scope`-фенса, поэтому мандатный путь гейта не тестируется вообще. Ни один зелёный прогон такого харнесса не является доказательством.

### 1.2 Границы (что делаем)

- Новый `config/tools/gov/scope_vectors.json` — язык-нейтральная таблица паритетных векторов (`pattern_cases` + `scope_cases`), которую читают **обе** стороны.
- Новый `config/bin/tests/test_scope_parity.py` — Python-сторона паритета (прогоняет векторы через `glob_match`/`scope_allows`).
- Правка `config/plugins/spec-gate.ts`: `globMatch` должен анкориться по **истинному концу** входа **флаг-независимо** (утверждение `"(?![\s\S])"` вместо `"$"`); наблюдаемый результат совпадает с `re.fullmatch` и сегодня не меняется (§1.1 п.1) — правка носит защитный характер.
- Правка `config/plugins/__tests__/spec-gate.test.ts`: изоляция хранилища одобрений, актуальный ассерт вместо устаревшего, `scope`-фенс в фикстуре, проверка мандатного пути (allow внутри / блок снаружи / `deny` побеждает), потребление той же таблицы векторов, независимость от cwd.
- Обновление ссылки на источник правды в комментарии `config/bin/spec_scope.py`.

### 1.3 Не-цели

- **Никаких изменений семантики** глобов (`*`, `?`, `[abc]`, `[!abc]`, `**`, `a/**` покрывает `a`). Меняется только форма записи якоря (флаг-независимость); наблюдаемые результаты всех векторов обязаны остаться прежними.
- Никаких изменений порядка принятия решения гейтом, exempt-списка, read-only allowlist, безусловного отказа `docs/**`, fail-closed на неразбираемых путях.
- Никаких новых рантайм-зависимостей: только stdlib (Python) и встроенные модули Node (TS). `package.json`/lockfile **не вводится**.
- Не трогаем `spec-preflight`, `wave-run`, `dod-run`, `spec-status`, `docs-lint`, `spec-approve`, `spec-revoke`.
- Никакой миграции `verify/<slug>/<id>.json` (P1-10) и никакой цепочки аудита — отдельные контракты.
- Никакой правки реального `~/.config/opencode`.
- **`config/plugins/**` и чужой `deny`.** Ранее запись в `config/plugins/**` блокировал `deny` из всё ещё активного завершённого контракта `preflight-0`: запреты побеждают любые `allow` по всей области, независимо от того, какой контракт их даёт. `preflight-0` переведён в `.slim/spec/archive/` (GOV-6, retire without delete) — его мандат больше не действует, а сам файл, запись об одобрении и evidence остаются на диске. После этого поле `allow` данного контракта действует полностью.

## Раздел 2. Архитектурное решение (Mini-ADR)

- **Контекст и проблема:** одна семантика — две реализации — ноль детекторов дрейфа; плюс недоверенный харнесс, который не может служить доказательством ни для одной правки гейта; плюс незакреплённая флаг-зависимость якоря (гипотеза о наблюдаемом расхождении при прямой проверке не подтвердилась — §1.1 п.1).
- **Принятое решение:**
  - таблица векторов — **данные**, а не код; обе стороны обязаны пройти её целиком. Добавление случая = одна строка JSON, а не правка двух алгоритмов;
  - паритет определён на **результате матча**, не на тексте регэкспа;
  - TS анкорится по истинному концу входа **флаг-независимо** — обе стороны строги и остаются строгими при любом флаге, а не «документированно разные»;
  - харнесс изолирует хранилище и проверяет мандат, значит его зелёный снова что-то значит.
  - Базовый ADR: `docs/adr/0001-gate-as-soft-guardrail.md`
- **Отвергнутые альтернативы:**
  - Альтернатива A — сравнение строк `globSource`/`glob_regex` — невозможно: разные экранирования дают разные строки при равной семантике; тест был бы ложным.
  - Альтернатива B — объявить анкоринг «документированной известной разницей» и не трогать `globMatch` — оставляет якорь зависимым от флагов регэкспа (сегодня не проявляется, но проявляется с `m`); для доверенного ядра недопустимо.
  - Альтернатива C — сгенерировать одну реализацию из другой (кодогенерация) — новый шаг сборки и новая зависимость ради ~40 строк.
  - Альтернатива D — тестировать TS, вызывая Python — это не паритетный тест, а проверка одной стороны через другую.
- **Последствия:**
  - Позитивные: дрейф становится падающим тестом; якорь гейта становится флаг-независимым (устраняется потенциальный, а не наблюдаемый сегодня класс расхождения); появляется воспроизводимое доказательство для **любой** будущей правки гейта.
  - Негативные / риски: правится **доверенный** плагин (митигация — минимальная правка, покрытая векторами, харнессом и независимым ревью); таблица векторов — новый артефакт, который надо поддерживать (митигация — это таблица, а не код).

**Связанные ADR.** `docs/adr/0001-gate-as-soft-guardrail.md` — почему мягкий гейт всё равно обязан быть точным на своей границе и почему доверенное ядро нельзя оставлять с расхождением; `docs/adr/0003-derived-lifecycle-state.md` — почему таблица векторов не является «второй истиной» о состоянии: это вход теста, а не хранилище вердикта.

## Раздел 3. Спецификация контрактов и интерфейсов (Reference)

> Нормативно. Реализация пишется строго по этому разделу.

### 3.1 `config/tools/gov/scope_vectors.json` — схема и обязательные случаи

```json
{
  "version": 1,
  "pattern_cases": [{"id": "plain-star", "rel": "src/a.ts", "pattern": "src/*.ts", "match": true}],
  "scope_cases":  [{"id": "deny-wins", "rel": "src/secret/x", "allow": ["src/**"], "deny": ["src/secret/**"], "allowed": false}]
}
```

Правила:
- `id` уникален внутри файла; ни один случай не может быть «пропущен» ни одной из сторон;
- `pattern_cases[]` проверяются через `glob_match` (Python) и `globMatch` (TS); `scope_cases[]` — через `scope_allows` (Python) и `scopeAllows` (TS);
- файл обязан содержать **все** перечисленные ниже случаи (это нормативный минимум, не пример).

Обязательные случаи:

| # | `rel` | `pattern` | `match` | что проверяет |
|---|-------|-----------|---------|----------------|
| 1 | `a` | `a/**` | `true` | `a/**` покрывает сам `a` |
| 2 | `a/b/c` | `a/**` | `true` | рекурсивный хвост |
| 3 | `ax` | `a/**` | `false` | `a/**` не покрывает `ax` |
| 4 | `a/b` | `a/*` | `true` | `*` матчит компонент |
| 5 | `a/b/c` | `a/*` | `false` | `*` не переходит `/` |
| 6 | `abc` | `a?c` | `true` | `?` — ровно один символ |
| 7 | `a/c` | `a?c` | `false` | `?` не матчит `/` |
| 8 | `ac` | `a?c` | `false` | `?` не ноль символов |
| 9 | `xyz` | `x[p-z]z` | `true` | класс-диапазон |
| 10 | `xaz` | `x[!p-z]z` | `true` | отрицание `[!…]` |
| 11 | `xpz` | `x[!p-z]z` | `false` | отрицание действительно отрицает |
| 12 | `a.b` | `a.b` | `true` | литеральная точка |
| 13 | `axb` | `a.b` | `false` | `.` в паттерне — литерал, не «любой символ» |
| 14 | `a+b` | `a+b` | `true` | литеральный `+` |
| 15 | `x/y` | `x/**/y` | `true` | `**` как компонент: ноль компонентов |
| 16 | `x/p/q/y` | `x/**/y` | `true` | `**` как компонент: много компонентов |
| 17 | `src/app.ts\n` | `src/*.ts` | `false` | **анкоринг по истинному концу** (нормативный вектор; сегодня выполняется обеими сторонами — §1.1 п.1 — и закрепляет флаг-независимость) |

Обязательные `scope_cases[]`: `deny` побеждает (`allow:["src/**"], deny:["src/secret/**"]` → `src/secret/x` = `false`, `src/ok/x` = `true`); пустой `allow` → `false`; паттерн вне `allow` → `false`; `a/**` покрывает `a` и внутри `scope`.

### 3.2 `config/bin/spec_scope.py` — существующая поверхность (не меняется)

`glob_match(rel, pattern) -> bool` (:365), `glob_regex(pattern) -> str` (:309), `scope_allows(scope, rel) -> bool` (:370), `scope_report(text) -> ScopeReport` (:260), `parse_scope(text) -> Scope|None` (:295).

Тест паритета обязан импортировать эти имена из `spec_scope` (не переписывать матчер).

Единственная правка: комментарий-указатель на источник правды (`:6-8`) должен называть **существующий** путь `config/tools/gov/scope_vectors.json`.

### 3.3 `config/plugins/spec-gate.ts` — требуемая правка `globMatch` (:469)

Нормативный наблюдаемый результат:

```js
globMatch("src/app.ts\n", "src/*.ts") === false
```

Рекомендуемая минимальная реализация: заменить якорь `"$"` на утверждение истинного конца (`"(?![\\s\\S])"`) либо отбрасывать вход, содержащий `\n`, до матчинга. Любая реализация с тем же наблюдаемым результатом допустима — решение принимает таблица векторов. Ничто иное в матчере не меняется.

**Поправка после прямой проверки (§1.1 п.1).** На Node v26.10.0 без флага `m` текущий код уже даёт `false`, поэтому требование — не «починить наблюдаемый дефект», а **закрепить флаг-независимость**: якорь `"$"` обязан быть заменён утверждением истинного конца. Критерий приёмки при этом не меняется и проверяется векторами: случай №17 = `false`, случай «без `\n`» = `true`, все остальные случаи без изменений. «Красное до» здесь недостижимо и **не требуется** (§4).

### 3.4 `config/plugins/__tests__/spec-gate.test.ts` — требуемое поведение

1. Команда запуска — `node --test config/plugins/__tests__/spec-gate.test.ts` **из корня репозитория** (проверено: Node v26.10.0 исполняет `.ts` нативно). Харнесс обязан быть независим от cwd: пути к плагину и к CLI (`config/bin/spec-approve`) резолвятся от собственного файла (`import.meta.dirname`/`fileURLToPath`), а не от `process.cwd()`.
2. Фикстуры остаются под `os.tmpdir()` через `mkdtempSync` и **никогда** не под `/tmp/opencode/**` (это exempt-префикс гейта, там блок-тесты бессмысленны).
3. Фикстурная спека **обязана** иметь валидный `scope`-фенс. Харнесс обязан доказать мандатный путь: запись внутри `allow` разрешена; запись вне `allow` блокируется (`[SPEC-GATE BLOCKED]`, reason `no-mandate`); `deny`-исключение побеждает `allow`.
4. Хранилище одобрений **изолировано**: харнесс не создаёт записей в реальном `~/.local/share/opencode/approvals/**` и проверяет, что реальное хранилище не изменилось. Рекомендуемый механизм — до загрузки модуля плагина перевести `HOME`/`XDG_DATA_HOME` на временный каталог (динамический `import()`) и передать CLI `--approvals-dir <tmp>/approvals`; если плагин резолвит хранилище иначе, харнесс пишет запись сам в это место.
5. Устаревший ассерт `out.endsWith(".json")` заменяется разбором текущего вывода CLI (`approved <spec> (sha256 <hex>)`, `gate: allow via <slug>`).
6. Харнесс читает `config/tools/gov/scope_vectors.json` и падает на любом расхождении по `pattern_cases` и `scope_cases`.
7. Отдельный тест-страж фиксирует инвариант изоляции хранилища (п.4).

### 3.5 Инварианты (строго LaTeX)

$$\operatorname{match}_{\text{TS}}(r,p) = \operatorname{match}_{\text{PY}}(r,p) \quad \forall\,(r,p)\in\text{vectors}$$

$$\operatorname{allow}(r) = \big(\exists\,a\in A:\operatorname{match}(r,a)\big)\ \land\ \neg\big(\exists\,d\in D:\operatorname{match}(r,d)\big)$$

$$r\neq s \Rightarrow \operatorname{match}(r,p)\ \text{и}\ \operatorname{match}(s,p)\ \text{вычисляются независимо (матч — чистая функция)}$$

## Раздел 4. Evidence Path (план доказательства корректности)

- **Стратегия:** `verification-planning`.
- **Юнит (Python):** `config/bin/tests/test_scope_parity.py` — прогоняет **все** случаи §3.1 через `glob_match`/`scope_allows`; отдельно проверяет, что пустой `allow` не разрешает ничего и что `deny` побеждает.
- **Юнит (TS):** тот же файл векторов через харнесс; плюс негативный тест `globMatch("src/app.ts\n", "src/*.ts") === false`; плюс мандатные тесты (allow/блок/deny); плюс страж изоляции хранилища.
- **Демонстрация (скорректирована после проверки §1.1 п.1):** «красного до» не существует — на Node v26.10.0 без флага `m` `globMatch("src/app.ts\n","src/*.ts")` уже `false`. Исполнитель обязан показать: (1) на **исходном** модуле случай №17 = `false`, то есть харнесс зелёный **до** правки; (2) после правки — те же зелёные результаты **плюс** доказательство флаг-независимости нового якоря (например: новый якорь даёт `false` и с добавленным флагом `m`, тогда как старый `"$"` с флагом `m` дал бы `true`). Именно (2) отличает «укрепили якорь» от «тест ничего не проверяет».
- **Чего в DoD нет и почему:** `spec-status --spec …` как чек не включён — состояние выводится из самого evidence, поэтому такой чек тавтологичен (ровно тот класс «театра верификации», который зафиксирован в `research/S5-reliability.md`). `docs-lint --spec …` включён: он проверяет целостность фенсов самой спеки.
- **Владение тяжёлым прогоном:** `config/bin/tests/test_scope_parity.py` и `docs-lint` — лёгкие; `node --test` — тоже. Все команды под троттлингом (`nice -n 19 taskset -c 0,1 ionice -c3`), одна тяжёлая команда за раз.
