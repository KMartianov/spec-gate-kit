## 3. Калибровочная сводка для M1/M2

- **Стоимость чека (время волны):** распределение R1/R10 — не гауссово; для модели M1 брать **медиану ~0.7 s** для статических/линт-чеков, **~22–30 s** для e2e/pytest, **~42 s** для ctest, **~190 s** для asan-стенда (p99 53 s, max 465 s — хвост из полных ctest/asan прогонов; `bin/dod-run` timeout 900 s, `exit_code:124` при таймауте).
- **Доля дублирующихся команд в волне (вход для оценки дедупликации M2):** R7–R9. Прямое измерение: **63% serial-wall волны** — дублирующиеся прогоны (ruff/pytest-unit/docs-untouched идентичны между контрактами). Модель M2 должна дать ~0.4 коэффициент сокращения при кешировании одинаковых `cmd` в рамках волны; асан-стенд (561 s × 3) — главный кандидат.
- **Цена многоагентного fan-out:** E8 (4× токенов на агента, 15× на multi-agent vs chat) и E13 (7× для agent teams) — калибровка стоимости волны воркстримов; E10 (3–5 параллельных subagent'ов, −90% времени) — верхняя граница ускорения при параллелизации; E11 — риск дублирования работ без явного разделения задач (прямое подтверждение важности `scope`-фенсинга).
- **Defect/throughput эффекты:** E1 (−19% для опытных разработчиков в незнакомых крупных репо) и E16 (DORA: AI ↑ производительность, ↓ stability) — пессимистичная и базовая границы для модели эффекта ревью-агентов; E9 (+90.2% на breadth-first) — оптимистичная граница для параллельного research.
- **$-калибровка:** E4 ($0.34/issue, agentless) — нижняя граница $/задачу для non-agent пайплайна; E7 ($13/дев/день Claude Code) — верхняя $/дев для интерактивного агента; E6 — пересчёт токен→$.
- **Надёжность канала:** R3 (100% `exit_code==0` и `tree_dirty=false` в актуальной эвиденции) — на этой машине DoD-чеки стабильны; отказоустойчивость в модели можно брать ≈1, но хвост R1 (p99 53 s) требует волнового таймаута с запасом ≥3× медианы.
- **Gate-фрикция:** R13–R15 — гейт блокирует 1.3% записей (98.7% allowed); реальных прод-блокировок 8 за всю историю (не тестовых), т.е. фрикция гейта в модели M1 мала (порядка 0.004 блокировки/сессию).

3. **Latency AI-ревью и defect rate ревью-агентов** — нет верифицированного публичного измерения в собранных источниках; Anthropic-блог по code-review не удалось получить (404).
4. **Токены/стоимость своих сессий OpenCode** — в `audit/spec-gate.jsonl` есть только `tool/targets/decision`, токенов и стоимости нет; `bin/oc-usage` измеряет rolling-окно, но human-only CLIs/записывающие операции не запускались; исторических данных о токенах на сессию в ките нет (`research/S6-economics.md:63`).
5. **Stale-доля по `spec_sha256` относительно текущих спек** — точная доля требует пересчёта хешей текущих файлов спек против эвиденции (последние `spec_sha256` в файлах не сверялись с фактическим байтовым состоянием спек; R11 — нижняя оценка).
6. **Anthropic API rate-limits** (E14 — только рекомендации из Claude Code docs, а не официальные лимиты API; страница API-лимитов закрыта region-редиректом).
